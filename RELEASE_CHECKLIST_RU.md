# Endless Brood 1.0.0-rc2 — проверка перед игровым выпуском

Это **кандидат в релиз**, а не проверенный игровой JAR. Исходники предназначены для Minecraft 1.7.10, Forge 10.13.4.1614, Java 8. Не класть ZIP в `mods`.

## 1. Сборка с настоящим Forge (обязательно)

1. Загрузить в GitHub содержимое ZIP (не сам ZIP).
2. Actions → `Build Minecraft 1.7.10 mod` → Run workflow.
3. Если Gradle падает, выгрузить полный лог ошибки — smoke-test не гарантирует совместимости с реальными API Forge.
4. Если сборка успешна, скачать `build/libs/EndlessBrood-1.7.10-1.0.0-rc2.jar` из GitHub Artifacts (путь и имя могут различаться по параметрам сборки).
5. Убедиться, что файл содержит `mcmod.info`, ресурсы и классы (не один только исходный код).

## 2. Одиночный мир

- Создать новый мир без других модов: открыть его, проверить журнал на ошибки FML.
- В творческом режиме создать каждое из 6 существ отдельным яйцом; проверить внешний вид, анимации, урон, дроп.
- В новом **и существующем** мире первые `threatGraceDays` игровых суток ПОСЛЕ ПЕРВОЙ УСТАНОВКИ (по умолчанию 3 = 60 реальных минут при 20 TPS) паразиты не появляются естественно и не получают пассивную эволюцию. Яйца призыва работают всегда.
- Проверить `/broodstage` без включения читов и изменение стадий при долгом выживании.
- Поставить гнездо в творческом режиме, временно уменьшить пороги стадий на тестовом мире (в финальной сборке возвращать значения).
- Испытать защиту: обсидиан и механизмы модов не должны прогрызаться; земля, дерево и камень — только при подходящей стадии и мутации; `mobGriefing=false` запрещает разрушение.
- Поставить подавитель и проверить обычные спавны, размножение колоний, копание и зачистку почвы.

- **Проверка отдалённого заражения:** загрузить копию старого мира, зайти обоим игрокам на базу в первые три игровых дня, подождать окончания форы, проверить отсутствие случайных паразитов и гнёзд ближе 768 блоков от исходных мест. Отправиться в дальние ранее исследованные чанки, убедиться, что ограниченное ретро-заселение создаёт гнёзда только при загруженном ландшафте и не насильно грузит чанки. Проверить сохранение мест базы и ретро-гнёзд после перезапуска сервера.

## 3. Два игрока / выделенный сервер

- Установить **одинаковый** JAR на оба клиента и сервер Forge 1.7.10; проверить подключение.
- Проверить одинаковую внешность паразитов у обоих игроков, сохранение генов после выхода и входа.
- Проверить, что прогресс эволюции один на весь мир, лимит за боевые действия общий для двух игроков.
- Перезагрузить сервер и проверить, что стадия, сопротивление урону и привязка паразитов к гнёздам сохраняются.

## 4. Совместимость с HBM Nuclear Tech Mod

- Сначала проверить Forge + Endless Brood; затем добавить конкретную установленную версию HBM NTM и её зависимости.
- Построить механизм/кабель NTM, поставить паразитов рядом, проверить что эти блоки не ломаются ими.
- Проверить попадания оружия NTM, работу радиационного урона и логи. Сопротивление распознаёт **название типа** урона, не все специальные эффекты HBM.
- Проверить скорость игры и TPS на пустой местности и около 3–5 гнёзд; при просадках уменьшить `naturalSpawnWeight`, `nestLocalPopulationLimit`, `nestChancePer10000Chunks`.
- Перед проверкой делать резервную копию мира.

## 5. Когда можно считать релиз готовым

Только после успешного Forge JAR, одиночной игры, выделенного сервера с двумя клиентами и прогона с той конкретной сборкой NTM, которую вы используете.
